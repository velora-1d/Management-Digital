## 2023-10-27 - Drizzle ORM GroupBy for Cashflow Time-Series
**Learning:** In the dashboard charts API (`src/app/api/dashboard/charts/route.ts`), fetching separate income and expense aggregates per month inside a `Promise.all` `.map()` loop generates 24 database queries (2 per month for 12 months). This N+1 pattern heavily degrades dashboard load times. Drizzle ORM supports combining this into a single SQL aggregation query using `groupBy`, `coalesce`, and `sum(case when...)`. Crucially, to extract the year and month correctly without timezone drift between Node.js and PostgreSQL, the SQL `extract` function must explicitly specify the local timezone (e.g., `AT TIME ZONE 'Asia/Jakarta'`). Correspondingly, when mapping these results back to the original date objects in Node.js, `Intl.DateTimeFormat` must be used with the exact same `timeZone` configuration. Relying on native `Date` methods causes off-by-one month bugs.
**Action:** Always prefer single `groupBy` aggregations over looped queries for time-series charts. Ensure SQL `extract` and JS `Intl.DateTimeFormat` both explicitly declare the local timezone to guarantee boundary synchronization.
